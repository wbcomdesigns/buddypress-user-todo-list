- **Namespace**: none — prefixed procedural functions + `Bptodo_*` classes
- **Text domain**: `wb-todo`
- **Prefixes**: functions `bptodo_*`, options `user_todo_list_settings` / `group-todo-list-settings` / `data-retention-settings`, CPT `bp-todo`, taxonomy `todo_category`, AJAX `bptodo_*`
- **Extends**: BuddyPress / BuddyBoss (OPTIONAL as of 4.0). Works standalone (personal todos via the My Todos block / [bptodo_list] shortcode on any page); BuddyPress adds profile tabs + group todos. Not a Free/Pro pair.

## Admin UI wrapper — OLD

### Admin CSS gotcha: `.bptodo-admin a` vs `.bptodo-btn`
`assets/css/admin.css` styles plain links with `.bptodo-admin a` (0,1,1), which outranks every
button variant (`.bptodo-btn-primary` etc., 0,1,0). An `<a class="bptodo-btn bptodo-btn-primary">`
therefore inherited accent-blue text on an accent-blue background - a button with an invisible
label. The rule is now scoped `.bptodo-admin a:not(.bptodo-btn)`. **Keep the `:not()`**, and when
adding a new button variant give it its own `color` - do not rely on the generic link rule.

### Never hardcode `admin.php?page=bp-components`
That screen only exists while BuddyPress is loaded, and on a network-activated install it lives in
network admin. Build it with BuddyPress's own helper,
`bp_get_admin_url( add_query_arg( array( 'page' => 'bp-components' ), 'admin.php' ) )`, inside a
`function_exists( 'bp_is_active' )` branch. With no BuddyPress at all, the link 403s with "Sorry,
you are not allowed to access this page" - show the "BuddyPress or BuddyBoss is not active."
empty state and link to `plugins.php` instead (see `includes/admin/views/settings-group.php`).

## Important patterns
- **Storage is CPT + postmeta** (no custom tables). Tasks = `bp-todo` posts; status/due-date/priority/group in postmeta.
- **All AJAX is admin-ajax, logged-in only** (no `wp_ajax_nopriv`). Member self-service nonce is `bptodo-todo-nonce` (localized as `todo_ajax_object.ajax_nonce`).
- **Release build** via `grunt` (`gruntfile.js`). Distribution zip lives in `dist/`.
- Settings are read through `Bptodo_Globals`; after admin save the global `$bptodo` is rebuilt in-place.

### Icons: Dashicons only, never Font Awesome
The plugin bundles **no icon font**. The legacy layout's action icons and spinner are core
**Dashicons** (`wp_enqueue_style( 'dashicons' )` in `Bptodo_Admin::bptodo_variables`), which cost
zero shipped bytes. The modern layout uses inline SVG and needs no icon font at all.

Do **not** reintroduce Font Awesome in any form - not from a CDN (a WP.org guideline breach and a
GDPR problem: it sends every visitor's IP to a third party without consent) and not bundled
(~1 MB of webfonts for a handful of glyphs). If you need a new icon, map it to a Dashicon.

`fa-spin` has no Dashicons equivalent, so the spin is a local `.bptodo-spin` class +
`@keyframes bptodo-spin` in `assets/css/bptodo-front.css` (with a `prefers-reduced-motion` guard).
Never pull in an icon library for an animation.

### jQuery UI
Core registers the jQuery UI **scripts** (`jquery-ui-datepicker` etc.) and the plugin correctly
uses those handles - it bundles no jQuery UI JS. Core ships **no jQuery UI stylesheet**, so the
theme CSS has to come from the plugin. `assets/css/jquery-ui.css` was previously misnamed
`jquery-ui.min.css` despite never being minified (1282 lines of readable CSS); it was renamed so
the name tells the truth and stops tripping "minified file with no source" review checks.

It is **locally patched** vs stock 1.12.1 base (tabs padding/panel rules changed; the
`.ui-widget` `font-family: Arial` override deliberately removed so jQuery UI does not force a
font on the active theme). Do not overwrite it with an upstream download. It is required: it
supplies the datepicker's structural CSS (`.ui-datepicker { width: 17em }`, table layout,
absolutely-positioned arrows) and the `images/ui-icons_*.png` sprites - the plugin's own
token-driven overrides in `bptodo-front.css` only restyle it, they do not replace it. Keep it in
`assets/css/` so the relative `images/` paths keep resolving.

### Select2: resolved, now the official dist (was a custom build with no source)
**RESOLVED 2026-07-17.** The bundle used to carry a custom 73,075-byte `select2.full.min.js`: a
real 4.1.0-rc.0 minified build, but with only 40 of the 43 AMD modules (missing
`select2/dropdown/attachContainer`, `select2/dropdown/stopPropagation`,
`select2/selection/stopPropagation`), matching no published artifact - so no honest source could
be shipped beside it and it stayed a WP.org violation.

It is now the **official 4.1.0-rc.0 dist**, min + source, both byte-identical to upstream
(verified identical across cdnjs, unpkg and jsDelivr: min 76,768 / source 167,106 bytes). Before
swapping, the old min was confirmed to be stock rc.0 and **not locally patched** - all 36 shared
module bodies were identical to the official build once minifier variable-mangling was normalized,
and `select2.min.css` was already byte-identical to upstream ignoring whitespace. The official
build is a strict superset, and the plugin only passes `placeholder` / `allowClear` / `width`, so
nothing about its behaviour changed.

Only two call sites exist; re-test both after any select2 change:
- `assets/js/admin.js` - `#bptodo_user_roles` (admin General tab role picker)
- `assets/js/bptodo-front.js` - `#todo_group_members` (group Add assignee picker)
